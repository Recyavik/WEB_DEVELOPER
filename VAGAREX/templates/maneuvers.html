Маневры — алгоритмы и функции управления

Полное описание всех алгоритмов движения и навигации робота 1T REX: схема, формула, реализация на Python с построчными комментариями, параметры и пример вызова. Все функции опираются только на примитивы из вкладки API 1T REX — их можно копировать на физическую плату как есть.

Оглавление

1. Базовые движения — forward / back · forward_to_wall · руль · RGB-индикатор
2. Одометрия — класс Odometry · duration_for_distance
3. Развороты и стороны света — turn_around_cmd (по дуге) · 3-дуговой K-turn (Reeds-Shepp) · face_cardinal_cmd (компас) · set_course_cmd · turn_around_place_cmd (зигзаг)
4. Маневры — круг · восьмерка · спираль · объезд (S-волна)
5. Навигация — goto_cmd / home_cmd · follow_path_cmd (Pure-pursuit)
6. Зоны и обстановка — mark_danger / алгоритмическая зона / remove
7. Режим осторожности — smart-direction K-turn + остановка перед препятствием

1. Базовые движения

1.1. forward / back — прямолинейное движение на расстояние

Идея

У робота нет энкодера колес. Расстояние пересчитываем через калибровку «скорость при 100% мощности»: v = SPEED_CM_PER_S_AT_100 × power / 100. Время удержания мотора:

duration = distance_cm / v = distance_cm × 100 / (SPEED_CM_PER_S_AT_100 × power_pct)

Назад — отрицательная мощность, длительность та же.

Параметры функции duration_for_distance(distance_cm, power_pct)

  • distance_cm — нужное расстояние в см. Только положительное; направление задается знаком мощности в robot.move.
  • power_pct — мощность мотора в процентах (по умолчанию DEFAULT_SPEED). Берется по модулю — направление неважно.

Пример вызова

# Едем 100 см вперед на 40% мощности.
robot.set_angle(0)                              # руль прямо — поедем строго вперед
duration = duration_for_distance(100, 40)       # 100 / (80 * 0.4) ≈ 3.13 с
robot.move(40, duration)                        # включить мотор на расчетное время
robot.stop()                                    # явная остановка после длительности

# Едем 100 см назад на 40% — отрицательная мощность.
robot.set_angle(0)                              # руль прямо
robot.move(-40, duration_for_distance(100, 40)) # минус → задний ход, длительность та же
robot.stop()                                    # остановиться

# Без duration — едем «бесконечно» до явного stop().
robot.move(40)                                  # поехали (мотор не выключится сам)
time.sleep(2.0)                                 # едем 2 секунды
robot.stop()                                    # остановились

1.2. forward_to_wall_cmd — движение до препятствия по дальномеру

Идея

Включаем мотор без аргумента duration (бесконечно) и в цикле читаем дальномер. Как только расстояние до препятствия опустится до stop_margin_mm (по умолчанию 150 мм = 15 см) — останавливаемся.

Шаг опроса 50 мс — компромисс между реакцией и нагрузкой на I²C-шину дальномера.

Параметры

  • power_pct — мощность мотора (по умолчанию DEFAULT_SPEED).
  • stop_margin_mm — минимальный «зазор» до препятствия в миллиметрах (150 мм по умолчанию).
def forward_to_wall_cmd(power_pct=DEFAULT_SPEED, stop_margin_mm=150):
    robot.move(power_pct)                                  # мотор без duration — едет до явного stop
    while True:                                        # бесконечный цикл, выход — break внутри
        dist = robot.get_laser()                           # расстояние в мм (или None — нет данных)
        if dist is None or dist <= stop_margin_mm:    # нет данных или подъехали слишком близко
            robot.stop()                                   # экстренная остановка
            break                                      # выйти из цикла
        time.sleep(0.05)                                   # 50 мс между опросами дальномера

Пример вызова

forward_to_wall_cmd()                  # до 150 мм перед стеной на DEFAULT_SPEED
forward_to_wall_cmd(60, 300)           # помедленнее (60%) и с большим зазором (30 см)

Замечание. Зеркальная функция backward_to_wall_cmd — то же самое, но с robot.move(-power_pct) и задним дальномером, если он есть (на 1T REX без заднего сенсора алгоритм опирается на одометрию).

1.3. Руль — set_angle(deg)

Идея

Серво-привод передних колес физически принимает значения −45…+45°. Сама ось колес не движется, пока стоит мотор — поворот видно только при последующем move().

Радиус разворота при максимальном угле:

R = 360 × WHEEL_CIRC_CM / (2π × HEADING_DEG_PER_ROT) ≈ 65 см

Пример вызова

robot.set_angle(36)        # направо на 36°
robot.set_angle(-36)       # налево на 36°
robot.set_angle(0)         # прямо (нейтраль)
robot.set_servo_center()   # эквивалент set_angle(0)

1.4. RGB-индикатор

Адресуем светодиод по индексу. Тройка (R, G, B) — 0..255. (0, 0, 0) — погасить. Параметр count — сколько светодиодов подряд (для адресной ленты).

Пример вызова

robot.set_rgb(0, (0, 255, 0), 1)   # зажечь зеленый, 1 диод (idx=0)
robot.set_rgb(0, (255, 80, 0), 1)  # оранжевый
robot.set_rgb(0, (0, 0, 0), 1)     # погасить

2. Одометрия — где находится робот

2.1. Класс Odometry

Зачем

На 1T REX нет GPS. Координаты (x, y) получаем интегрированием перемещения за каждый малый шаг времени:

Δs = SPEED_CM_PER_S_AT_100 × power_pct/100 × Δt
x ← x + Δs · sin(heading)
y ← y + Δs · cos(heading)

Курс heading берем с гироскопа: robot.get_angle()['Z']. Это намного точнее интегрирования угла поворота колес.

Параметры конструктора

  • x, y — стартовая позиция в см (по умолчанию START_X_CM, START_Y_CM).
  • heading — стартовый курс в градусах (0..359, 0 = север).

Параметры move_step(power_pct, duration_sec, steer_deg=0)

  • power_pct — мощность мотора, та же что в robot.move.
  • duration_sec — длительность шага в секундах.
  • steer_deg — угол руля во время шага (для коррекции курса).
class Odometry:
    def __init__(self, x=START_X_CM, y=START_Y_CM, heading=START_HEADING_DEG):
        self.x = float(x)                       # текущая координата по оси X в см
        self.y = float(y)                       # текущая координата по оси Y в см
        self.heading = float(heading)           # курс: 0=север (+y), 90=восток (+x)

    def sync_heading(self):
        # Подменить интегральный heading реальным курсом с гироскопа.
        # Делать каждые 5..10 шагов, чтобы не накапливать ошибку поворота.
        z = robot.get_angle().get('Z')        # 'Z' = yaw в градусах
        if z is not None:                       # гироскоп может вернуть None при инициализации
            self.heading = float(z) % 360.0     # нормализуем в [0; 360)

    def move_step(self, power_pct, duration_sec, steer_deg=0):
        # Вызывать ПОСЛЕ каждого robot.move(...). Δs = v·Δt.
        sign     = 1 if power_pct >= 0 else -1                # знак направления (вперёд/назад)
        cm_per_s = SPEED_CM_PER_S_AT_100 * abs(power_pct) / 100.0    # фактическая скорость в см/с
        ds       = cm_per_s * duration_sec                           # пройденная длина по дуге в см
        if abs(steer_deg) > 1:                                       # был поворот руля → корректируем heading
            steer_ratio = steer_deg / 45.0                           # нормировка на максимум 45°
            d_head = HEADING_DEG_PER_ROT * (ds / WHEEL_CIRC_CM) * steer_ratio * sign  # Δкурса по геометрии Аккермана
            self.heading = (self.heading + d_head) % 360.0           # обновить курс, нормализовать в [0;360)
        rad = math.radians(self.heading)                             # градусы → радианы для тригонометрии
        self.x += sign * math.sin(rad) * ds                          # sin — ось X идёт вправо
        self.y += sign * math.cos(rad) * ds                          # cos — ось Y идёт вверх

odo = Odometry()                                                     # глобальный экземпляр для goto_cmd / follow_path_cmd

Пример использования

# Едем 50 см вперёд на 60% мощности и сами обновляем одометрию.
duration = duration_for_distance(50, 60)     # расчёт длительности по дистанции и мощности
robot.set_angle(0)                           # руль прямо
robot.move(60, duration)                     # едем 60% на расчётное время
odo.move_step(60, duration, 0)               # обновить (x, y) после движения
robot.stop()                                 # явная остановка
print(odo.x, odo.y, odo.heading)             # где мы теперь — координаты и курс

2.2. duration_for_distance(distance_cm, power_pct)

def duration_for_distance(distance_cm, power_pct=DEFAULT_SPEED):
    # Сколько секунд держать мотор на power_pct, чтобы пройти distance_cm.
    speed_cm_s = SPEED_CM_PER_S_AT_100 * abs(power_pct) / 100.0   # см/с при заданной мощности
    return max(0.05, distance_cm / max(1.0, speed_cm_s))           # защита: power=0 → не делим на 0

Пример вызова

duration_for_distance(100, 40)   # 100 см на 40% → ≈ 3.13 с
duration_for_distance(50,  80)   # 50 см на 80% → ≈ 0.78 с

3. Развороты курса

В роботе доступны два пользовательских разворота на 180°:

  • 3.1 turn_around_cmd — обычный разворот: одна большая K-turn-пара (петля-«teardrop»). Кнопка «↺ Разворот», голос «Вега разворот». Нужна свободная зона ≈ 1.3 м.
  • 3.5 turn_around_place_cmd — разворот на месте: N коротких пар «вперёд-право → назад-лево» (≈ 30°/пара). Кнопка «↺ На месте», голос «Вега разворот на месте». Помещается в тесном пространстве.

Дополнительные функции этого раздела — не отдельные команды «развернуться», а смежные алгоритмы ориентации:

  • 3.2 kturn_cmd (Reeds-Shepp) — внутренний помощник для поворота на произвольный угол Δh. Используется внутри face_cardinal_cmd, отдельной кнопки/голоса не имеет.
  • 3.3 face_cardinal_cmd — повернуться лицом к стороне света (С/Ю/В/З и т.д.). Кнопки компаса, голос «Вега на север».
  • 3.4 set_course_cmd — выйти на нужный курс плавной дугой на ходу (без разворота на месте).

3.1. turn_around_cmd — разворот на 180° (K-turn-пара)

Идея

Одна K-turn-пара: робот сначала едет вперёд с рулём в сторону разворота (~1.5 c), затем перекладывает руль в зеркало и едет назад столько же. Геометрия Аккермана гарантирует, что робот возвращается ≈ в исходную точку, но курс развёрнут на 180°.

Зона разворота — небольшая «петля» диаметром ≈ 1.3 м (зависит от калибровки). В тесном пространстве — используйте turn_around_place_cmd с большим количеством шагов.

Параметры

  • direction — +1 разворот по часовой (вправо), -1 — против часовой (влево).
  • power_pct — мощность мотора (по умолчанию DEFAULT_SPEED).
def turn_around_cmd(direction=1, power_pct=DEFAULT_SPEED):
    # Один K-turn-шаг: робот возвращается в исходную точку,
    # курс развёрнут на 180°. Траектория — «петля» (teardrop).
    robot.set_angle(direction * DEFAULT_TURN_ANGLE)    # руль в сторону разворота
    robot.move(power_pct, 1.5)                         # вперёд по дуге (≈ 1.5 с)
    robot.set_angle(-direction * DEFAULT_TURN_ANGLE)   # руль в зеркальную сторону
    robot.move(-power_pct, 1.5)                        # назад по зеркальной дуге
    robot.stop()                                       # окончательный стоп
    robot.set_servo_center()                           # вернуть руль в нейтраль

Пример вызова

turn_around_cmd()         # разворот направо на 180° (по умолчанию +1)
turn_around_cmd(-1)       # разворот налево на 180°
turn_around_cmd(1, 60)    # разворот направо на скорости 60%

Что делает симулятор сверху алгоритма

Перед K-turn-парой симулятор автоматически выполняет:

  • Проверка clearance. По геометрии Reeds-Shepp считается, сколько свободного пространства нужно ВПЕРЁД (≈ R·sin(α) + 20 см запаса, для 180° получается ~92 см). Если впереди стена ближе — робот сначала отъезжает назад на нужную величину (ограничено доступным местом сзади). В журнале: «⚠ Для разворота нужно 92 см впереди, есть 45. Отъезжаю назад на 47 см».
  • Возврат в исходную точку. После K-turn-пары из-за погрешностей физики робот может уехать на 30-40 см от старта. Итеративно: P-регулятор довозит обратно (фаза 2), затем мелкими дугами 5-8° корректирует курс (фаза 3). Цикл до 5 итераций.

В сгенерированный Python-код эти проверки не попадают — они специфичны для симулятора. На реальном роботе нужно добавить свою логику проверки границ (или просто доверять оператору, что места хватит).

3.2. 3-дуговой K-turn (Reeds-Shepp) — разворот на месте

Геометрия Reeds-Shepp

Чтобы развернуться на угол Δh (в градусах) и вернуться в исходную позицию, выбираем такие α (вперед) и β (назад), чтобы:

2α + β = |Δh|
sin(β/2) = sin(|Δh|/2) / 2

Из второго уравнения β однозначно вычисляется, потом α = (|Δh| − β)/2. Полный цикл: forward(α) → backward(β) → forward(α) при максимальном угле руля. Гироскоп контролирует фактический поворот в каждой дуге.

Параметры

  • delta_deg — на сколько градусов нужно повернуть курс (по модулю).
  • direction — +1 по часовой, -1 против часовой.
  • power_pct — мощность мотора.
def kturn_cmd(delta_deg, direction=1, power_pct=DEFAULT_SPEED):
    delta = abs(delta_deg)                                                  # работаем с положительным углом
    beta  = 2 * math.degrees(math.asin(math.sin(math.radians(delta/2)) / 2))# дуга назад β по формуле Reeds-Shepp
    alpha = (delta - beta) / 2                                              # дуги вперёд α (две одинаковые)

    def arc(target_dh, power_sign, steer_sign):                         # внутренняя функция — одна дуга
        # Едем, пока |фактическое изменение курса| не достигнет target_dh.
        h0 = robot.get_angle()['Z']                                # курс на старте дуги
        robot.set_angle(steer_sign * DEFAULT_TURN_ANGLE)                    # руль на полный угол в нужную сторону
        robot.move(power_sign * power_pct)                                  # без duration — крутим до условия
        while True:                                                     # опрашиваем гироскоп каждые 50 мс
            cur = robot.get_angle()['Z']                            # текущий курс с гироскопа
            done = abs(((cur - h0 + 540) % 360) - 180) >= target_dh         # знаковая разница ≥ цели?
            if done:                                                    # дуга пройдена
                robot.stop()                                                # останавливаем мотор
                break                                                   # выходим из цикла
            time.sleep(0.05)                                                # 50 мс между проверками гироскопа

    arc(alpha, +1, +direction)                  # дуга 1: вперёд, руль в сторону разворота
    arc(beta,  -1, -direction)                  # дуга 2: назад, руль в обратную сторону (sign−)
    arc(alpha, +1, +direction)                  # дуга 3: вперёд, руль снова в сторону разворота
    robot.set_servo_center()                    # вернуть руль в нейтраль

Пример вызова

kturn_cmd(90)        # повернуться на 90° по часовой
kturn_cmd(180, -1)   # развернуться на 180° против часовой
kturn_cmd(45,  +1)   # повернуться на 45° по часовой

3.3. face_cardinal_cmd(target_deg) — повернуться лицом к стороне света

Идея

Тонкая обёртка вокруг K-turn: считает кратчайшую разницу курса по формуле:

diff = ((target − heading + 540) mod 360) − 180

Это даёт знаковый угол в диапазоне [−180; +180]: положительный — поворот по часовой (вправо), отрицательный — против часовой (влево). Затем вызывается kturn_cmd(|diff|, sign(diff)).

Условие |diff| < 3° — деадзона, чтобы не дёргать робота на мелких рассинхронизациях гироскопа.

Параметры

  • target_deg — целевой курс в градусах (0=север, 90=восток, 180=юг, 270=запад).
def face_cardinal_cmd(target_deg):
    cur  = robot.get_angle()['Z']               # текущий курс с гироскопа
    diff = ((target_deg - cur + 540) % 360) - 180   # кратчайший знаковый угол [-180..+180]
    if abs(diff) < 3:                            # уже почти смотрим куда надо
        return                                   # ничего не делаем (дед-зона)
    direction = +1 if diff > 0 else -1         # знак невязки → направление поворота
    kturn_cmd(abs(diff), direction)                 # делегируем 3-дуговой K-turn

Пример вызова

face_cardinal_cmd(0)     # встать лицом на север
face_cardinal_cmd(45)    # на северо-восток
face_cardinal_cmd(90)    # на восток
face_cardinal_cmd(135)   # на юго-восток
face_cardinal_cmd(180)   # на юг
face_cardinal_cmd(225)   # на юго-запад
face_cardinal_cmd(270)   # на запад
face_cardinal_cmd(315)   # на северо-запад

Что делает симулятор сверху алгоритма

То же самое, что у turn_around_cmd:

  • Перед K-turn — проверка clearance (помещается ли разворот), и при необходимости автоматический отъезд назад на безопасное расстояние.
  • После K-turn — возврат в исходную точку (фаза 2: P-регулятор) и коррекция курса (фаза 3: мелкие дуги по 5-8°), итеративно до 5 раз пока не сойдётся к ±1.5 см / ±1.5°.

3.4. set_course_cmd(target_deg) — выставить курс на ходу

Идея

Применяется, когда впереди есть запас места и можно «домотать» курс одной плавной дугой без K-turn. Угол руля пропорционален невязке курса с ограничением:

steer = clip(diff, ±DEFAULT_TURN_ANGLE)
duration = |diff| / 30°/с

Это простой пропорциональный регулятор: чем больше отклонение от цели, тем сильнее повёрнут руль (до максимума).

Параметры

  • target_deg — целевой курс в градусах.
  • power_pct — мощность мотора (по умолчанию DEFAULT_SPEED).
def set_course_cmd(target_deg, power_pct=DEFAULT_SPEED):
    cur  = robot.get_angle()['Z']                          # текущий курс с гироскопа
    diff = ((target_deg - cur + 180) % 360) - 180              # знаковая невязка [-180..+180]
    # P-регулятор по углу руля с насыщением: пропорция 1:1, ограничение ±DEFAULT_TURN_ANGLE.
    steer = max(-DEFAULT_TURN_ANGLE, min(DEFAULT_TURN_ANGLE, diff))  # clip угла руля до пределов серво
    robot.set_angle(int(steer))                                # подать руль на расчётный угол
    robot.move(power_pct, abs(diff) / 30.0)                    # длительность ~ |diff|/30°/с
    robot.stop()                                               # стоп после прохождения дуги

Пример вызова

set_course_cmd(90)        # выйти на курс 90° (восток) дугой
set_course_cmd(180, 60)   # на юг, помедленнее (60% мощности)

3.5. turn_around_place_cmd — разворот на месте N парами

Кнопка «↺ На месте» в панели управления и голосовая команда «Вега разворот на месте» вызывают именно эту функцию. Отличие от turn_around_cmd: вместо одной большой петли — много маленьких (по ≈ 30° курса каждая), поэтому разворот помещается в тесном пространстве.

Идея

Альтернатива 3-дуговому K-turn: для тесных мест и неточной калибровки лучше делать много мелких пар «вперёд+право → назад+лево» по 0.5 секунды каждая. Каждая пара поворачивает робот примерно на 2 × HEADING_DEG_PER_ROT × (0.5с × DEFAULT_SPEED/100 × SPEED_CM_PER_S_AT_100) / WHEEL_CIRC_CM ≈ 30° на пару при стандартной калибровке.

Для разворота на 180° нужно ~6 пар (steps=6). Не требует сложной геометрии — отлично работает и без точного гироскопа.

Параметры

  • steps — количество пар «вперёд-назад». 6 пар ≈ 180°, 3 ≈ 90°.
  • power_pct — мощность мотора (по умолчанию DEFAULT_SPEED).
def turn_around_place_cmd(steps, power_pct=DEFAULT_SPEED):
    for i in range(steps):                          # N пар маленьких подёргиваний
        robot.set_angle(DEFAULT_TURN_ANGLE)             # руль вправо
        robot.move(power_pct, 0.5)                      # вперёд 0.5 с — поворачиваемся ~15°
        robot.set_angle(-DEFAULT_TURN_ANGLE)            # руль влево
        robot.move(-power_pct, 0.5)                     # назад 0.5 с — ещё ~15° в ту же сторону
    robot.stop()                                        # окончательный стоп
    robot.set_servo_center()                            # вернуть руль в нейтраль

Пример вызова

turn_around_place_cmd(6)     # разворот на 180° за 6 пар
turn_around_place_cmd(3)     # поворот на 90° за 3 пары
turn_around_place_cmd(12)    # полный круг 360° (если место позволяет)

Что делает симулятор сверху алгоритма

  • Перед стартом — проверка clearance (для разворота на 180° нужно ~92 см вперёд, для 90° — ~50 см). При нехватке отъезд назад.
  • После последней пары — возврат в исходную точку + коррекция курса (та же фаза 2+3, что и у обычного K-turn).

4. Маневры

4.1. circle_cmd — один полный круг

Идея

Кладем руль на максимум, едем full_turn_sec ≈ 4 секунды — как раз 360°. По умолчанию направление CCW (против часовой, математическое 0→2π). Если в команде явно «направо/по часовой» — CW (direction=+1).

Параметры

  • direction — -1 CCW (против часовой, по умолчанию), +1 CW (по часовой).
  • power_pct — мощность мотора.
  • full_turn_sec — время полного оборота в секундах (зависит от калибровки, по умолчанию 4.0).
def circle_cmd(direction=-1, power_pct=DEFAULT_SPEED, full_turn_sec=4.0):
    robot.set_angle(direction * DEFAULT_TURN_ANGLE)   # руль на полный угол в нужную сторону
    robot.move(power_pct, full_turn_sec)              # одна непрерывная дуга 360°
    robot.stop()                                      # стоп после полного оборота
    robot.set_servo_center()                          # вернуть руль в нейтраль

Пример вызова

circle_cmd()              # круг против часовой на DEFAULT_SPEED
circle_cmd(+1)            # круг по часовой
circle_cmd(-1, 60, 5.0)   # медленнее (60%) и подольше (5 с) — круг побольше

4.2. figure_eight_cmd — восьмерка

Идея

Робот стартует с касательной точки между двумя кругами. Первый полный круг при руле direction × max возвращает его в исходную точку. Затем руль перекладывается в зеркало −direction × max, и второй полный круг идет в обратную сторону. Получается классическая восьмерка: ∞.

Радиус каждого круга ≈ 65 см при максимальном угле руля, общая ширина траектории ≈ 2.6 м.

Параметры

  • direction — направление первого круга. -1 = CCW (по умолчанию), +1 = CW. Второй круг — в противоположную сторону.
  • power_pct — мощность мотора.
  • full_turn_sec — время одного полного круга (≈ 4 с).
def figure_eight_cmd(direction=-1, power_pct=DEFAULT_SPEED, full_turn_sec=4.0):
    robot.set_angle( direction * DEFAULT_TURN_ANGLE)    # руль в сторону первого круга
    robot.move(power_pct, full_turn_sec)                # первый полный круг (360°)
    robot.set_angle(-direction * DEFAULT_TURN_ANGLE)    # перекладка руля → второй круг в зеркало
    robot.move(power_pct, full_turn_sec)                # второй полный круг в обратную сторону
    robot.stop()                                        # стоп после двух кругов
    robot.set_servo_center()                            # вернуть руль в нейтраль

Пример вызова

figure_eight_cmd()             # первый круг CCW, второй CW
figure_eight_cmd(+1)           # первый CW, второй CCW
figure_eight_cmd(-1, 70, 3.5)  # побыстрее (70%), круги покрупнее

4.3. spiral_cmd — спираль (наружу / внутрь)

Идея

За один шаг едем чуть-чуть (micro_sec = 0.3 c), и каждый раз меняем угол руля по линейной интерполяции от steer_from до steer_to. Чем меньше угол → больше радиус → спираль раскручивается.

steer(i) = steer_from + (steer_to − steer_from) × i / (N−1),   где N = turns × 360 / 5

Для спирали внутрь — поменять from и to местами (24°→36°): радиус будет уменьшаться.

Параметры

  • direction — -1 CCW (по умолчанию), +1 CW.
  • power_pct — мощность мотора.
  • steer_from — стартовый угол руля в градусах (36° для «наружу»).
  • steer_to — конечный угол руля (24° для «наружу»).
  • turns — сколько витков сделать (по умолчанию 2).
  • micro_sec — длительность одного микро-шага в секундах (0.3 с).
def spiral_cmd(direction=-1, power_pct=DEFAULT_SPEED,
               steer_from=36, steer_to=24, turns=2, micro_sec=0.3):
    total_steps = int(turns * 360 / 5)                              # шаг ~5° курса на микро-шаг
    for i in range(total_steps):                          # итерируемся по микро-шагам
        t = i / max(1, total_steps - 1)                             # нормированное время 0..1
        steer_deg = steer_from + (steer_to - steer_from) * t        # линейная интерполяция угла руля
        robot.set_angle(int(direction * steer_deg))                 # корректируем угол перед каждым шагом
        robot.move(power_pct, micro_sec)                            # едем micro_sec и меняем угол снова
    robot.stop()                                                    # стоп после N шагов
    robot.set_servo_center()                                        # вернуть руль в нейтраль

Пример вызова

spiral_cmd()                                          # спираль наружу, CCW, 2 витка
spiral_cmd(+1)                                        # спираль наружу, CW
spiral_cmd(-1, steer_from=24, steer_to=36)            # спираль внутрь (радиус уменьшается)
spiral_cmd(-1, steer_from=36, steer_to=10, turns=3)   # 3 витка с очень широким финалом

4.4. bypass_cmd — объезд препятствия (S-волна)

Идея

4 равные четверти-дуги, каждая по quarter_sec ≈ 0.5 c. Знак угла руля чередуется: фазы 0 и 3 — в сторону объезда, фазы 1 и 2 — возврат на исходную линию. После четырех фаз робот снова на старой линии движения.

Параметры

  • start_dir — +1 объезд справа (сначала вправо), -1 объезд слева.
  • max_steer — максимальный угол руля в градусах (по умолчанию 36°).
  • power_pct — мощность мотора.
  • quarter_sec — длительность одной четверти-дуги в секундах (0.5 с).
def bypass_cmd(start_dir=1, max_steer=36, power_pct=DEFAULT_SPEED, quarter_sec=0.5):
    for phase in range(4):                            # 4 четверти-дуги: ┌╮ ╭┘
        # Фазы 0,3 — в сторону объезда; фазы 1,2 — возврат на исходную линию.
        sign = start_dir if phase in (0, 3) else -start_dir   # знак руля для текущей фазы
        robot.set_angle(sign * max_steer)               # подать руль на нужный знак
        robot.move(power_pct, quarter_sec)              # проехать одну четверть-дугу
    robot.stop()                                        # стоп после 4 фаз
    robot.set_servo_center()                            # вернуть руль в нейтраль

Пример вызова

bypass_cmd(+1)               # объезд справа
bypass_cmd(-1)               # объезд слева
bypass_cmd(+1, 30, 60, 0.7)  # помягче (30°), помедленнее, побольше радиус

5. Навигация по координатам

5.1. goto_cmd(x, y) — перейти в точку

Алгоритм

  1. Считаем целевой курс: bearing = atan2(x−x₀, y−y₀) (атан2 от Δx и Δy, потому что 0° = север = +y).
  2. Невязку diff = bearing − heading приводим к интервалу [−180; +180].
  3. Shortcut: если |diff| ≤ 30° — едем сразу вперёд через drive_to_point_closed_loop.
  4. Если |diff| ≥ 150° — едем задом (мощность отрицательная, та же closed-loop с зеркальным bearing).
  5. Иначе — выполняем face_cardinal_cmd(bearing) и потом прямой проезд через drive_to_point_closed_loop.

Closed-loop коррекция курса. Вместо одного «слепого» проезда (open-loop) робот едет короткими шагами (≈ 100 мс). На каждом шаге читает гироскоп, считает текущую невязку курса до цели и подруливает. Если робота сбило (зацепился при развороте, гироскоп дрейфанул, кто-то толкнул) — на следующем такте курс будет автоматически скорректирован, и робот всё равно доедет до цели.

Оптимизация на этапе генерации кода. В момент добавления команды кодогенератор смотрит на ТЕКУЩИЕ позицию и курс робота (важно: до фактического выполнения команды) и выбирает один из четырёх режимов:

  • skip — distance < 5 см. Робот уже в цели. В код пишется # уже в точке (x, y).
  • forward — bearing к цели в пределах ±5° от текущего курса. В код пишется простой robot.move(+speed, ...) без вызова goto_cmd и его зависимостей. Helper из преамбулы — только duration_for_distance.
  • backward — bearing противоположен курсу (180°±5°). То же самое, но с минусовой мощностью — едем задом без разворота.
  • goto — произвольное направление. В код пишется полный goto_cmd(x, y), преамбула тянет всю инфраструктуру: Odometry, face_cardinal_cmd, drive_to_point_closed_loop, goto_cmd.

Это и читать проще, и выполняется быстрее, и преамбула получается минимальная: для типового сценария «вперёд 100 → юг → ещё вперёд» в коде будет пара robot.move(...) вместо нескольких сотен строк def-блоков.

bearing = atan2(target_x − x, target_y − y)
diff = (bearing − heading + 540) mod 360 − 180
steer = clip(kp × diff, ±DEFAULT_TURN_ANGLE),   kp = 0.7

Параметры

  • target_x, target_y — координаты цели в см от старта.
  • power_pct — мощность мотора (по умолчанию DEFAULT_SPEED).
  • tolerance_cm — допустимая ошибка в см (по умолчанию 5 см).
# Closed-loop проезд: едем короткими шагами и подруливаем по гироскопу.
# Если робота сбило (зацепился, толкнули, дрейф) — на следующем такте
# курс будет скорректирован, и робот всё равно доедет до цели.
def drive_to_point_closed_loop(target_x, target_y, power_pct, tolerance_cm,
                               step_sec=0.1, kp=0.7):
    sign = 1 if power_pct >= 0 else -1                     # знак: вперёд / назад
    robot.move(power_pct)                                         # мотор без duration — крутим до явного stop
    while True:                                               # шагаем по step_sec секунд (по умолчанию 100 мс)
        odo.sync_heading()                                        # каждый такт — реальный курс с гироскопа
        dx = target_x - odo.x; dy = target_y - odo.y              # вектор от робота к цели
        dist = math.hypot(dx, dy)                                 # текущая дистанция до цели
        if dist < tolerance_cm:                               # дошли — выходим из цикла
            break
        bearing = math.degrees(math.atan2(dx, dy)) % 360.0        # куда сейчас «смотрит» цель
        if sign < 0:                                          # задним ходом — целимся «зеркально»
            bearing = (bearing + 180.0) % 360.0
        diff = (bearing - odo.heading + 540.0) % 360.0 - 180.0    # знаковая невязка курса
        steer = max(-DEFAULT_TURN_ANGLE, min(DEFAULT_TURN_ANGLE, diff * kp))  # P-регулятор
        robot.set_angle(int(steer))                               # подать руль на расчётный угол
        odo.move_step(power_pct, step_sec, steer)                 # учесть прошедшие 100 мс в одометрии
        time.sleep(step_sec)                                      # подождать следующего такта
    robot.stop()                                                  # финальная остановка
    robot.set_servo_center()                                      # вернуть руль в нейтраль


def goto_cmd(target_x, target_y, power_pct=DEFAULT_SPEED, tolerance_cm=5):
    odo.sync_heading()                                            # обновить курс из гироскопа
    dx = target_x - odo.x                                         # смещение по X (см)
    dy = target_y - odo.y                                         # смещение по Y (см)
    distance = math.hypot(dx, dy)                                 # √(Δx² + Δy²) — длина прямой
    if distance < tolerance_cm:                               # уже на месте — выходим
        return
    target_heading = math.degrees(math.atan2(dx, dy)) % 360.0     # целевой курс
    bearing = ((target_heading - odo.heading + 540) % 360) - 180  # знаковая невязка курса

    if abs(bearing) < 30:                                     # Цель почти прямо
        # Едем сразу с коррекцией курса по гироскопу.
        drive_to_point_closed_loop(target_x, target_y, power_pct, tolerance_cm)
    elif abs(bearing) > 150:                                  # Цель почти позади
        # Едем задом с коррекцией курса (closed-loop сам зеркалит bearing).
        drive_to_point_closed_loop(target_x, target_y, -power_pct, tolerance_cm)
    else:                                                     # Общий случай
        # Сначала разворот на месте, потом проезд с коррекцией.
        face_cardinal_cmd(target_heading)                         # встать лицом к цели через K-turn
        odo.sync_heading()                                        # перечитать курс после поворота
        drive_to_point_closed_loop(target_x, target_y, power_pct, tolerance_cm)


def home_cmd():
    goto_cmd(START_X_CM, START_Y_CM)                              # возврат в стартовую точку (домой)

Пример вызова

goto_cmd(100, 0)         # перейти в точку (100, 0)
goto_cmd(150, 200, 60)   # перейти в (150, 200) на скорости 60%
home_cmd()               # вернуться в стартовую точку

5.2. follow_path_cmd(points) — Pure-pursuit за waypoint'ами

Алгоритм Pure-pursuit

  1. На каждом такте найти ближайшую точку пути.
  2. От нее пройти вперед по пути, пока накопленная длина не превысит lookahead_cm (горизонт планирования).
  3. Считать bearing на эту «целевую» точку и подать в руль: steer = clip(0.7 × diff).
  4. Повторять с шагом 100 мс, пока не дошли до конца пути.
bearing = atan2(tx − x, ty − y) ;    steer = clip(0.7 × (bearing − heading))

Используется в режиме осторожности после построения пути A* с обходом красных зон.

Параметры

  • points — список [(x1,y1), (x2,y2), ...] точек пути в см.
  • power_pct — мощность мотора.
  • lookahead_cm — горизонт планирования в см. None = автовычисление (≈ 1.5 длины робота).
  • tolerance_cm — допустимая ошибка достижения конца (5 см).
def follow_path_cmd(points, power_pct=DEFAULT_SPEED, lookahead_cm=None, tolerance_cm=5):
    if not points or len(points) < 2:                                # нужен хотя бы 1 сегмент пути
        return                                                         # пустой путь — сразу выходим
    if lookahead_cm is None:                                       # параметр не передан — авторасчёт
        lookahead_cm = max(30.0, ROBOT_LENGTH_CM * 1.5)                  # дефолт ≈ 1.5 длины робота
    gx, gy = points[-1]                                                  # финальная точка пути (для условия выхода)
    last_idx = 0                                                         # индекс последней «ближайшей» точки
    robot.set_angle(0)                                                   # руль прямо — стартовое положение
    robot.move(power_pct)                                                # едем без duration — крутим до конца
    while True:                                                       # основной цикл pure-pursuit (100 мс/такт)
        odo.sync_heading()                                               # держим курс актуальным с гироскопа
        if math.hypot(gx - odo.x, gy - odo.y) < tolerance_cm:           # дошли до финала?
            break                                                       # да — выходим из цикла
        # 1) Ближайшая точка пути от last_idx (никогда не «откатываемся»).
        best_i, best_d2 = last_idx, float('inf')                     # лучший индекс и квадрат расстояния
        for i in range(last_idx, len(points)):                       # перебираем точки начиная с прошлой ближайшей
            d2 = (points[i][0] - odo.x)**2 + (points[i][1] - odo.y)**2   # квадрат дистанции (без sqrt — быстрее)
            if d2 < best_d2:                                            # нашли точку ближе
                best_d2, best_i = d2, i                                  # обновляем «лучшую»
            elif d2 > best_d2 + 100:                                    # точки начали отдаляться
                break                                                   # дальше нет смысла искать — выходим
        last_idx = best_i                                                # запомнить — со следующего такта стартуем отсюда
        # 2) Цель = точка впереди на lookahead_cm по длине пути.
        target_i, accum = best_i, 0.0                                    # индекс цели и накопленная длина
        for i in range(best_i, len(points) - 1):                     # шагаем вперёд по сегментам
            accum += math.hypot(points[i+1][0] - points[i][0],           # длина сегмента (Pythagoras)
                                points[i+1][1] - points[i][1])
            if accum >= lookahead_cm:                                   # перешли горизонт планирования
                target_i = i + 1                                         # берём следующую точку как цель
                break
        else:
            target_i = len(points) - 1                                   # дошли до конца — целимся в финал
        tx, ty = points[target_i]                                        # координаты цели на этом такте
        # 3) Bearing на цель и руль с насыщением (P-регулятор × 0.7).
        bearing = math.degrees(math.atan2(tx - odo.x, ty - odo.y))       # направление на цель в градусах
        diff    = ((bearing - odo.heading + 540) % 360) - 180            # знаковая невязка [-180..+180]
        steer   = max(-DEFAULT_TURN_ANGLE, min(DEFAULT_TURN_ANGLE, diff * 0.7))  # P-регулятор с насыщением
        robot.set_angle(int(steer))                                      # подать руль на расчётный угол
        odo.move_step(power_pct, 0.1, steer)                             # обновить (x, y) за прошедшие 100 мс
        time.sleep(0.1)                                                  # 100 мс шаг управления
    robot.stop()                                                         # финальная остановка мотора
    robot.set_servo_center()                                             # вернуть руль в нейтраль

Пример вызова

path = [(0, 0), (50, 50), (100, 50), (150, 100), (200, 200)]
follow_path_cmd(path)                  # следовать за waypoint'ами на DEFAULT_SPEED
follow_path_cmd(path, 60, 25)          # помедленнее (60%), горизонт 25 см (точнее реакция)

6. Зоны обстановки

6.1. Красные (опасные) и алгоритмические зоны

Различие

  • Красная зона — реальное препятствие на местности (опасная для робота). Сохраняется как часть карты обстановки, влияет на планировщик A* и режим осторожности.
  • Алгоритмическая (желтая) — внутренний контейнер алгоритма (исключение из планирования, временный буфер). Не часть реальной карты, удаляется по окончанию миссии.

Параметры

  • x, y — координаты центра зоны в см.
  • radius — радиус зоны в см.

7. Режим осторожности — поведение перед препятствием

7.1. Smart-direction K-turn

Идея

Симметричные маневры (face_cardinal_cmd, set_course_cmd, turn_around_cmd) выполняются в одном «естественном» направлении (по часовой). В режиме осторожности:

  1. Симулируем все три дуги K-turn в исходном направлении. Если ни одна точка дуги не пересекает красную зону — выполняем как обычно.
  2. Если пересечение есть — повторяем симуляцию для зеркального направления.
  3. Если оба направления блокированы — отказываемся выполнять и предлагаем в журнале альтернативу (например, goto_cmd(x, y) с обходом A*).

Параметры

  • delta_deg — на сколько градусов нужно повернуть (по модулю).
  • danger_zones — список [(x, y, radius), ...] зон опасности.
# Симуляция трёх дуг K-turn без реального движения робота — для проверки на зоны.
def simulate_kturn(start_x, start_y, start_h, delta_deg, direction, danger_zones):
    pts = []                                                              # список точек симулированной траектории
    delta = abs(delta_deg)                                                # работаем с положительным углом
    beta  = 2 * math.degrees(math.asin(math.sin(math.radians(delta/2)) / 2))  # дуга назад β по Reeds-Shepp
    alpha = (delta - beta) / 2                                            # дуги вперёд α (две одинаковые)
    x, y, h = start_x, start_y, start_h                                   # текущие позиция и курс в симуляции
    for arc_deg, power_sign, steer_sign in [
            (alpha, +1, +direction),                                      # дуга 1: вперёд
            (beta,  -1, -direction),                                      # дуга 2: назад (зеркальный руль)
            (alpha, +1, +direction)]:                                     # дуга 3: вперёд
        steps = max(2, int(arc_deg / 5))                                  # дискретизация ~5° на шаг
        for _ in range(steps):                                       # микро-шаги внутри одной дуги
            ds = power_sign * 2.0                                         # 2 см/шаг (со знаком направления)
            dh = HEADING_DEG_PER_ROT * (ds / WHEEL_CIRC_CM) * (steer_sign * DEFAULT_TURN_ANGLE / 36.0)  # Δкурса за шаг
            h  = (h + dh) % 360.0                                         # обновить курс (нормализация в [0;360))
            x += ds * math.sin(math.radians(h))                           # обновить X (sin — ось x вправо)
            y += ds * math.cos(math.radians(h))                           # обновить Y (cos — ось y вверх)
            pts.append((x, y))                                            # запомнить точку траектории
            for (zx, zy, zr) in danger_zones:                         # проверка на пересечение каждой зоны
                if (x - zx)**2 + (y - zy)**2 < zr*zr:                     # попали внутрь круга радиуса zr
                    return None                                          # траектория небезопасна
    return pts                                                        # все шаги пройдены — траектория свободна


def kturn_smart_cmd(delta_deg, danger_zones):
    # Пробуем сначала «по часовой»; если не получилось — против часовой.
    for direction in (+1, -1):                                    # перебираем оба направления
        traj = simulate_kturn(odo.x, odo.y, odo.heading,                  # симулируем K-turn для проверки
                              delta_deg, direction, danger_zones)
        if traj is not None:                                     # направление безопасно
            kturn_cmd(delta_deg, direction)                               # выполняем по-настоящему
            return True                                              # успех
    return False                                                      # оба направления блокированы — отказ

7.2. Остановка перед препятствием

Для прямолинейных команд (forward, goto_cmd) в режиме осторожности проверяем дальномер перед каждым микро-шагом. Алгоритм такой же, как в forward_to_wall_cmd, только при срабатывании дальномера вместо выхода — приостанавливаем команду и предлагаем в журнале изменить ее на goto_cmd(x, y) с обходом A* по карте красных зон.

Параметры

  • distance_cm — целевое расстояние в см.
  • power_pct — мощность мотора.
  • stop_margin_mm — минимальный зазор до препятствия (по умолчанию 200 мм).
def safe_forward(distance_cm, power_pct=DEFAULT_SPEED, stop_margin_mm=200):
    micro_sec = 0.1                                                       # шаг управления 100 мс
    target    = duration_for_distance(distance_cm, power_pct)             # общее время на всю дистанцию
    elapsed   = 0.0                                                       # уже потраченное время
    robot.move(power_pct)                                                 # едем без duration — крутим до явного stop
    while elapsed < target:                                           # пока не пройдено всё запланированное время
        d = robot.get_laser()                                             # расстояние до препятствия в мм
        if d is not None and d <= stop_margin_mm:                    # слишком близко — препятствие!
            robot.stop()                                                  # экстренная остановка
            # Зафиксировать препятствие как красную зону на 30 см впереди робота:
            mark_danger_cmd(odo.x + 30 * math.sin(math.radians(odo.heading)),  # X препятствия (по курсу)
                            odo.y + 30 * math.cos(math.radians(odo.heading)),  # Y препятствия (по курсу)
                            radius=20)                                    # радиус опасной зоны 20 см
            return "blocked"                                       # вызывающий код переключится на goto_cmd + A*
        time.sleep(micro_sec)                                             # подождать перед следующим тактом
        elapsed += micro_sec                                              # учесть прошедшие 100 мс
        odo.move_step(power_pct, micro_sec, 0)                            # обновить (x, y) на каждом шаге
    robot.stop()                                                          # финальная остановка после прохода
    return "ok"                                                # дошли до цели без срабатывания дальномера

Пример вызова
